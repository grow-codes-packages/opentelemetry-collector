# AGENTS.md — Grow Codes SDK for OpenTelemetry Collector (`opentelemetry-collector`)

Instructions for AI coding agents and humans working in this repository. `CLAUDE.md` is a symlink to
this file. Service-specific notes (vendor quirks, API coverage, emulator limits) live in
`docs/compatibility.md`, the README "Function overview" and `skills/opentelemetry-collector-sdk/SKILL.md`.

## What this repository is

One API for OpenTelemetry Collector in five languages, generated from
[sdk-kit](https://github.com/grow-codes-packages/sdk-kit) (version in `.sdk-kit.json`) and
completed with service code. Categories: **logging,tracing**. The contract for every package is the
sdk-kit specification (`SPEC.md` in sdk-kit): names, defaults, error codes, environment variables,
category interfaces and the Docker contract.

## Generated files rule

- A file whose first lines contain `Generated by sdk-kit <version> — do not edit` belongs to sdk-kit.
  **Do not edit it here.** Change sdk-kit (template), release it, then run `sdk-kit sync` in this
  repository. A local edit is detected (`.sdk-kit.json` keeps a SHA-256 per file) and blocks the
  next sync until it is reverted or forced.
- To take over a generated file for good, delete its header line; sync then leaves it alone.
- Never edit `conformance/` or `.sdk-kit.json` by hand.
- `sdk-kit check` (run in CI) verifies that the required files, badges and workflows are present.

## API parity rule

The five packages expose the **same** functions, options, defaults, error codes and behaviour. Any
change to the public API lands in all five languages in the same pull request, with unit tests in
each and an integration call in the Docker suite. Names follow each language's convention:

| | TypeScript | Rust | Go | Python | Java |
| - | - | - | - | - | - |
| Methods | `camelCase` | `snake_case` | `PascalCase`, `ctx` first | `snake_case` | `camelCase` |
| Errors | `OtelCollectorError` + subclasses | `Error` enum, `code()` | `*Error`, `errors.Is(err, otelcollector.ErrNotFound)` | `OtelCollectorError` + subclasses | `OtelCollectorException` + subclasses |
| Durations | `…Ms` numbers | `Duration` | `time.Duration` | seconds (`…_s`) / `timedelta` | `Duration` |
| Async | `Promise` + `AbortSignal` | `async` + `blocking` feature | sync with `ctx` | sync + `AsyncOtelCollectorClient` | sync + `…Async` |

If one language truly cannot support something, document it in `docs/compatibility.md`.

## Tests and coverage

- Unit tests run against local mock HTTP servers; they never need network access or Docker.
- **Coverage gates** (CI-enforced, first-party code only): TypeScript, Python and Java ≥ 90 % lines
  **and** ≥ 90 % branches; Rust ≥ 90 % lines and ≥ 90 % regions; Go ≥ 90 % statements.
- Unit conformance tests are named after the ids in `conformance/core-unit.md`.
- Test fakes for users of the package ship in the testing module (TypeScript
  `@grow-codes/opentelemetry-collector/testing`, Rust feature `testing`, Go `testkit`, Python
  `grow_opentelemetry_collector.testing`, Java `codes.grow.packages.otelcollector.testing`).

## Docker integration rules

- `docker/compose.yml` runs `otel/opentelemetry-collector-contrib:0.165.0` plus a one-shot `bootstrap` service that writes credentials
  to `/bootstrap/env`. Tests read that file and `GROW_OPENTELEMETRY_COLLECTOR_URL`.
- Each language has a `test-<lang>` service (profile `<lang>`). Its Dockerfile packs the package and
  installs it into the consumer project in `<lang>/integration/`, which runs the integration tests
  and the conformance runner.
- Always run through `make test-docker`: it uses a unique Compose project per run, publishes no host
  ports and always runs `docker compose down -v`, even on failure or Ctrl-C.
- Every public function is called at least once against the real service with a round-trip
  assertion. Functions the service cannot serve are listed in `docs/compatibility.md` and covered by
  unit tests.

## Release rules

- Releases are made by [release-please](https://github.com/googleapis/release-please) from
  Conventional Commits on `main` (`feat:`, `fix:`, `feat!:`). Never bump versions or edit
  `CHANGELOG.md` by hand. Use the language as the scope when a change touches one package.
- One release pull request covers all five packages. Tags: `typescript-vX.Y.Z`, `rust-vX.Y.Z`,
  `go/vX.Y.Z` (the Go module lives in `go/`, so its tag must be `go/v…` for `go get` to work),
  `python-vX.Y.Z`, `java-vX.Y.Z`.
- The release workflow publishes to npm, crates.io, PyPI and Maven Central; Go is published by its
  tag. Publishing credentials live only in the release environment of the GitHub repository.

## OpenTelemetry Collector specifics

- **Service modules** (service code in every language): config + client (`health` with the zpages
  fallback, `waitUntilReady`, `ping`, `serverVersion`, `close`), `CollectorHealthClient`,
  `initTelemetry` → `TelemetryHandle`, `initTracing` with collector defaults, OTLP log exporter +
  `createLogClient`, metric helpers + runtime metrics, resource detection, and the query clients
  (always `UNSUPPORTED`). File map: TypeScript `src/{client,config,health,telemetry,setup,logs,metrics,resource,otlp,query}.ts`;
  Rust `src/{client,config,health,telemetry,setup,logs,metrics,resource,otlp,query,blocking}.rs`;
  Go `{client,config,health,telemetry,tracing,logs,otlp,resource,query}.go`; Python
  `src/grow_opentelemetry_collector/{client,config,health,telemetry,setup,logs,metrics,resource,otlp,query}.py`;
  Java `codes.grow.packages.otelcollector.{OtelCollectorClient,OtelCollectorConfig,CollectorHealthClient,OtelCollectorTelemetry,TelemetryHandle,OtelCollectorTracing,OtlpLogExporter,OtelCollectorMetrics,ResourceDetector,Otlp,…}`.
- **Binding decisions** (keep all five languages on them):
  - Env precedence: explicit > `GROW_OPENTELEMETRY_COLLECTOR_*` > `GROW_OTEL_*` (alias) >
    per-signal `OTEL_EXPORTER_OTLP_<SIGNAL>_*` > generic `OTEL_*` > default. No `TOKEN` setting:
    credentials go in `headers` (`OTEL_EXPORTER_OTLP_HEADERS`).
  - Protocols `http/protobuf` (default, 4318) and `grpc` (4317); `native` → `CONFIG`.
    `grpcUrl` defaults to the scheme and host of `url` on port 4317. An explicit per-signal URL
    wins in **both** protocols (`endpointFor(signal)`), also for the gRPC `ping()` target.
  - `health()`: `health_check` (13133), then zpages `/debug/servicez` (55679); admin endpoints never
    get the export headers; no retries. `serverVersion()`: zpages "Version" row, then `target_info`
    at `telemetryUrl`, else `UNSUPPORTED`. `ping()` = empty OTLP trace export.
  - OTLP exports use the official exporters' retries; the shared transport only serves
    health/ping/version. Export errors keep the natural `retryable` flag of their code.
  - gRPC status mapping (same table everywhere, see `docs/compatibility.md`): 3/9/11/13 →
    `VALIDATION`, 5/12 → `NOT_FOUND`, 6 → `CONFLICT`, 7 → `PERMISSION_DENIED`, 8 → `RATE_LIMITED`,
    16 → `AUTHENTICATION`, 4 → `TIMEOUT`, 1 → `CANCELLED`, everything else → `UNAVAILABLE`.
  - Every call on a closed client (including the factories) → `CANCELLED`.
  - gRPC + `insecureSkipVerify` → `CONFIG` in Python and Rust (grpcio/tonic cannot skip).
- **Wire traps**: oversized bodies get HTTP 400 (not 413); malformed gRPC messages get `INTERNAL`;
  `tracez` is 404 in 0.165.0; the stock config binds `health_check` to localhost (the fixture
  overrides it; platform follow-up: bind it to `0.0.0.0` in stacks).
- **Docker**: two collectors (`opentelemetry-collector` with `docker/config/collector.yaml`,
  `opentelemetry-collector-stock` with the image's built-in config), a Jaeger 2.23.0 sidecar, a
  busybox `capture` httpd serving the file exporter output, a `bearertokenauth` receiver on
  4319/4320 with a per-run token, and `bootstrap/` which sends canary telemetry and writes
  `/bootstrap/env`. The scratch collector image is health-checked with a static busybox from a
  shared volume. Read-back adapters (Jaeger, capture files) are test-only and live in each
  `integration/` project.
- Unit-test-only cases and server/language differences: `docs/compatibility.md`.

## Rules for agents

- Keep secrets out of code, tests, fixtures, logs and commit messages. Credentials are always wrapped
  in the redacting secret type; error messages pass through redaction.
- Runtime dependencies must use a licence from the allowlist: Apache-2.0, MIT, BSD-2-Clause,
  BSD-3-Clause, ISC, Zlib, Unicode-3.0, Unicode-DFS-2016, 0BSD, CC0-1.0, MPL-2.0. Never GPL, LGPL,
  AGPL, SSPL, BUSL or EPL at runtime.
- Keep dependencies small; prefer the standard library.
- Before you push: `make lint coverage` for every language you touched (or all of them for shared
  changes), and `make test-docker LANGS="<lang>"` when behaviour against the service changed.
- Update the README function overview, `docs/` and the skill file when the public API changes.
